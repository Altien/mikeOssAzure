# v0.4.0-azure.2 — container security patch

A patch release over `v0.4.0-azure.1`. It changes no application code and
no behaviour: the only change is to the `Dockerfile`, clearing three
Critical CVEs that were present in the image the previous tag built.

## Upstream tracking

This line tracks upstream open-source Mike **v0.4.0** (commit `dafac6b`,
20 July 2026) — <https://mikeoss.com>. `azure.2` adds no upstream
changes over `azure.1`; both build the same application code.

## What changed

| Fix | Why |
|---|---|
| `npm` 12.0.1 → 12.0.2 | The floor for CVE-2026-59873 (`tar`, unbounded resource allocation) moved to `tar` 7.5.19. npm 12.0.1 ships 7.5.15; 12.0.2 depends on `^7.5.19`. |
| `libnss3` named in the apt layer | Picks up the Debian bookworm security update for CVE-2026-16389 (fixed in `2:3.87.1-1+deb12u4`) rather than whatever the base image froze at. |
| corepack's pnpm cache removed | The build already disabled corepack and deleted its binary, but left `/root/.cache/node/corepack` behind — and with it a second copy of the vulnerable `tar` in the runtime image. This completes that removal. |

Criticals in the built image: **7 → 4**.

## What is left, and why

Four Critical CVEs remain, all in Debian bookworm packages inherited from
the `node:22-slim` base image, and all currently marked *not fixed*
upstream:

- `perl` — CVE-2026-13221, CVE-2026-12087
- `openssl` — CVE-2026-75803
- `tiff` — CVE-2026-52490

There is no patched version to move to. They clear when the base image
rebases onto a Debian release carrying the fixes; nothing in this
repository can resolve them sooner. They were equally present in
`v0.4.0-azure.1`.

## Verifying

```sh
docker build -t mike-backend:local .
docker scout cves mike-backend:local --only-severity critical
```

Expect four Criticals, in the four packages named above. Any Critical in
`tar` or `nss` means the image predates this patch.
